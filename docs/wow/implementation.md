# WOW implementation

The approved transport-first rebrand is implemented in the existing React 19/TypeScript/Vite project. Four actual HTML entries support direct loading and refresh: Home, About, Tracking and Contact. Shared React navigation replaces the original header controller, which is disabled in the adapted runtime. Internal navigation bypasses legacy Barba interception.

Home retains the original globe renderer, AVIF crane/truck frame sequences, Three.js ocean/wake, ship and aircraft media. Following the latest annotated feedback, the continuous route ribbon and the flight/footer route lines are removed. New compositions, an original wordmark, cloud arrangements, concise text, client notes, courier directory, FAQs and footer provide the WOW identity.

The latest user correction supersedes the geography-led marketing draft. The hero now reads “Shipping. Made simple.” Other page titles use direct service language. Geographic location is factual contact information. There are no “From India” or “India at heart” slogans in the delivered interface.

`src/content/site.ts` is the content source. `tools/wow/prepare_story.mjs` preserves the original structural input and generates WOW transport trees; it replaces numerical proof blocks with service labels and rewrites both desktop and phone service variants. `adapt_runtime.mjs` always starts from original archived modules, localises resources, disables the old header and unused section controllers, preserves the shader-disposal fix and exposes a lifecycle bridge. Generated files are rebuilt before dev/build. The prior recovery generator exits without writing when WOW content is present.

The retained transport section controllers are Hero, Intro, Service and Why. A scoped WOW FlightChapter uses the same aircraft/cloud media with a shorter sticky pass, replacing the original testimonial-coupled overlap and its empty holds. Long original testimonials, unrelated Insight/Partners/FAQ/CTA/Footer controllers, airline marks, fixed awards badge, news strip, calculator, old tracking portal, source contact data, payment claims and unsupported metrics are excluded from the active interface. Client notes, the neutral directory, native FAQ, closing CTA and footer are authored React components.

Desktop navigation is horizontal above 1024px. Below that width a labelled menu traps focus, supports Escape and restores focus to its trigger. Home retains the original phone `.body-inner` scroll owner. Other pages scroll natively, with short GSAP entry/chapter reveals. A reduced-motion Home uses the same content and static transport imagery without loading the scene runtime. Services anchors wait for runtime readiness and warm the initial sections before scrolling to the target.

Tracking has a real provider-independent Web Request handler. No provider was selected, so the current configured behavior is explicit `NOT_CONFIGURED` with support access. Provider selection and credentials remain integration prerequisites. Netlify now supplies the production function adapter and platform rate limiting. Tests inject providers only in test code; the website contains no sample live shipment.

Contact validates trimmed required fields and phone digit counts, creates an encoded WhatsApp message and keeps the prepared text available when a popup is blocked. It sends nothing to a server. Actual sending remains the visitor’s action in WhatsApp. The primary number is +91 7973546092; email is info@wowshippings.com; location is Mohali, Punjab.

Original assets and old reconstruction evidence remain preserved. The website is now published at https://wow-shipping.netlify.app/ through the authorized Netlify account. No external message, payment, Git commit or paid media generation was performed.

The latest flight pass moves the right-facing aircraft from -10% to +10% along its horizontal axis, holding rotation and scale constant. Reverse scrolling retraces the same pass. The shared footer reuses the original particle scatter/reassembly physics, extracted by `tools/wow/prepare_particles.mjs` into an isolated module. Its image mask is typeset as WOW SHIPPING locally after font readiness. Rendering pauses offscreen, DPR is capped at 2, pointer coordinates use the live canvas bounds, and click/Enter/Space can scatter the lettering. Reduced motion uses static text without a canvas. A retained dotted world-map image sits behind the footer information with low opacity and no pointer interception.

Inner pages now have their own interactive narrative. About uses `ShipmentStory` for Understand → Coordinate → Stay connected, with original container/truck/aircraft imagery, reversible scene changes and native chapter links. Contact uses the same chapter system after its enquiry form; its live `ShipmentBrief` reflects service choice, origin, destination and completion of three detail groups. Service buttons and the form select stay in sync. A prominent jump link reaches the form directly on phones. Tracking keeps its AWB form first and adds a keyboard-accessible, four-state courier-status guide below it. The guide explains statuses separately from actual tracking results.

Shared page motion is scoped to its React root. Existing GSAP/ScrollTrigger modules provide reveals, vehicle movement and chapter activation without loading the Home/WebGL runtime on inner pages. A ResizeObserver refreshes measurements when a WhatsApp draft or tracking result changes page height. MatchMedia restores static presentation on a live reduced-motion change. Chapter content stays in native document flow; no scroll lock or extra rendering dependency is introduced.

Home's sea-to-air transition is restored with the existing cloud image layered across the section boundary. Scroll progress brings cloud cover over the sea, parts the foreground banks, and reveals the aircraft and copy. It reverses with upward scrolling and retains the corrected nose-first flight path. No source carrier identity or new route ribbon is restored.
